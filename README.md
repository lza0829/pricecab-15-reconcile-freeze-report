# 06-pricecab（价签柜）

Pricecab — 改价单按预约时刻生效，现行价签可查，并与销售夹具对账（对账结论可冻结成报告、可复查）。

与 Feedstitch（多源归并）、Batchgate（作业编排）、Syncledger（双端对账）、Changecast（CDC 投影）、Proofpack（采样放行）主链路不同。  
不是电商订单/购物车，不是仓库进出库 CRUD，不是考勤 OA。夹具全本地。

## 启动

```bash
docker compose up --build
```

| 入口 | 地址 |
| --- | --- |
| 前端 | http://localhost:5600 |
| API | http://localhost:10600 |

## 主链（0-1）

选商品建改价单（写明生效时刻）→ 拨业务钟或点「应用到期」→ 现行价签更新 → 生成对账冻结报告（钉扎业务钟与价格历史水位），结论可复查

## 对账冻结报告

「销售对账」页是**现场重算的挥发性预览**：每次调用重读现行价格历史，新应用一发生结论就变，不能当固定结论。需要可复查的结论时到「冻结报告」页生成报告。

生成时钉扎两份基线，并写进报告：

- **业务钟**：报告代表的「截至某业务时刻」的结论；
- **价格历史水位**（`price_history.id`）：只取水位之内的历史行，生成后的应用不会改变报告内任何数字。

报告存下当时的逐笔一致 / 不一致 / 缺价集合与分桶计数（票号、钉扎钟点、水位、来源改价单、价格历史行 id 全部落库）。打开报告时按同一水位重放比对，界面显示「与存档一致 / N 行漂移」。

### 旧报告命运（二选一策略）

应用到期改写价签后，批次之前的报告按当前策略处理，二选一：

| 策略 | 行为 |
| --- | --- |
| `void` 旧报告作废（默认） | 标「已作废」，查询明确标作废、`is_current=false`，不得再当现行结论；须用新业务钟或新水位重切报告。 |
| `archive` 旧报告只读存档 | 标「非现行 · 只读存档」，仍可打开复查，但现行结论只能来自最新未作废报告。 |

策略可在「冻结报告」页或应用时选择；应用正在处理的策略与本批次的退役结果会随批次返回。

### 生成与应用互斥

生成报告与「应用到期」共用一把数据库内的 ops 锁（`ops_locks`），两者互斥：

- 报告钉扎中途点「应用到期」→ `409`，应用被拒绝，价签不会在钉扎过程中被改写；
- 应用进行中生成报告 → `409`，报告被拒绝。

报告写入的退役标记与应用改写价签在同一个事务里提交，不会出现「价签已改、报告状态却没变」的半截状态。
